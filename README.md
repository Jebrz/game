# 星空列车（第一阶段原型）

中文单人星空列车生存经营游戏。你是被神秘规则选中的列车长，带领 30 名幸存者驾驶旧列车，沿古老星际轨道在灾变「灰烬潮」到来前撤离，前往公共交易站休整。

基于 **Vite + TypeScript**，界面为 DOM + Canvas 程序绘制，不依赖外部素材。

> 本仓库原有的地下城游戏已完整保留：分支 `backup/dungeon-game`（已推送）与本地标签 `dungeon-backup-2026-11-04`。
> 原公开部署来自 `claude/serene-ritchie-qv18mk` 分支，本分支未改动它；本分支的 Pages 工作流已改为仅手动触发，不会自动发布。

## 启动

需要 Node.js 18+。

```bash
npm install
```

```bash
npm run dev
```

浏览器打开 <http://localhost:5173/>。

其他命令：

```bash
npm run check   # 类型检查 + 测试
```

```bash
npm run build   # 类型检查 + 生产构建到 dist/
```

```bash
npm run preview # 预览生产构建：http://localhost:4173/game/
```

## 操作

| 操作 | 说明 |
| --- | --- |
| 空格 | 暂停 / 继续（暂停冻结生产、消耗、移动与灾变） |
| 1 / 2 / 3 / 4 | 速度 1× / 2× / 4× / 8×（加速只增加固定步数，不会重复结算） |
| T / M | 列车剖视 / 星球地图 |
| 点击车厢 | 打开对应面板（车头→列车，居住车→乘客，后勤车→奖励政策，工程车→库存加工，科研车→研究基因） |
| 地图悬停 | 查看迹象、矿点作业位置、运输机状态 |
| 右侧标签 | 列车、小组、运输机、库存加工、奖励政策、研究基因、乘客、情绪安保、灾变召回、交易站 |
| 存档 / 读档 | 顶栏右侧。自动存档 + 2 个手动槽位 |

左上角「第一阶段目标」随进度更新，并给出当前提示（例如还缺哪种原料）。

## 第一阶段流程

列车苏醒 → 启动列车扫描（只揭示资源迹象）→ 小组自主探索确认矿点 → 运输机抵达后先到先得取得作业位置、采矿、返航交付 → 车内加工维修零件、修复主驱动 → 制造轨道燃料 → 小组用贡献点自主升级运输机或做基因强化 → 灾变逼近、紧急召回 → 离站航行 → 抵达回声交易站完成一次补给或维修 → 阶段总结（之后可继续在站内查看列车）。

一局约 18～20 游戏小时（含 4 小时航行）。1× 速度下 1 真实秒 = 2 游戏分钟，整局约 9～10 分钟真实时间；加速可更快。

## 已实现

- **列车与乘客**：车头 + 5 节可用车厢（居住×2、后勤生活、工程货运、科研医疗）+ 2 节封闭车厢（标注未开放）。30 人（列车长、5 名负责人、24 名乘客，**临时测试名单**），含职业、技能、健康、疲劳、情绪、基因适配度。岗位按职业自动分配，普通岗位低技能可低效工作，医疗岗位有技能门槛 40。
- **编组**：列车长规定每组各职业人数，乘客自行组队；负责人与列车必需运营人员（工程 2、后勤 2、医疗 1）不出勤；一人不进多个小组；不满足时显示缺少什么。默认 2 个小组。
- **扫描与探索**：低级探测仪只给迹象范围；小组实地探索确认（含一处“迹象微弱、无矿”的迹象）；发现自动同步；一个简短的非阻塞事件「古代轨道信标」。
- **作业位置**：大矿区多位置；抵达部署时才取得；返航交货保留 120 分钟（界面显示剩余时间），过期释放；采空释放；等待最多 40 分钟后重新评估，不会无限等待。
- **小组自主决策**：综合收益、航程、燃料、运载空间、成员能力、风险与组长性格（稳健/进取），状态与理由可见（如“选择较近矿点以降低运输成本”“因燃料不足返航”“等待其他位置释放”）。列车推进剂告急时小组会优先采冰晶。
- **运输机**：采集型、探索型两架（总数固定，不凭空生成）；运载量、采矿效率、航速、油耗、耐久与例行维护；可购买升级「扩容货舱」「强化钻头」。运输机推进剂与列车轨道燃料分开。列车长可配属/释放座机（亲自探索为后续内容）。
- **贡献点**：交付时货物转入列车库存，按「基础价 + 需求奖励」结算，每批次只结算一次；列车长可调需求奖励并即时显示新价格；小组自主购买（运输机升级 vs 基因强化），显示理由、费用与结果，无审批窗口。超出基本任务半径的航程由小组额度支付。
- **加工**：维修零件、轨道燃料、运输机推进剂、电解制氧；入队即预留原料，取消退还，无负库存。
- **研究与基因**：「采掘适应序列解析」解锁「采掘适应序列·一阶」（贡献点 + 生物样本 + 能源 + 在岗医护 + 适配度/健康/疲劳 + 承载上限 1 + 恢复期 90 分钟）；未实现序列显示为未开放。
- **生存**：食物、氧气、能源、疲劳、健康；医疗自动治疗；正常流程无随机死亡。
- **情绪**：士气、失望、敌意分开；个人等权汇总；持续高失望累积敌意，降低失望不会立刻清除敌意；显示影响因素。
- **私人武装机器人**：数量、状态、威慑、维持耗能、待机/巡逻；威慑不降低敌意；敌意满值不直接判负。
- **灾变**：预计到达时间区间（越近越准）；逼近预警、危险边缘首次自动暂停；抵达后车体持续受损，车体归零才失败。
- **召回与离站**：紧急召回，查看各组位置、返回预计、载荷、推进剂、未归人员；离站需主驱动修复 + 轨道燃料 10 + 全员归队；可强行离站（遗留人员与运输机，敌意大增，需确认）。
- **交易站**：停泊费、每小时停泊费、买卖、车体与运输机维修、站内禁止暴力、灾变追赶进度暂停（不清零）、阶段完成总结。
- **存档**：版本号；自动存档（每 60 游戏分钟与阶段变化）+ 2 个手动槽位；完整保存小组行动、矿点占用、货舱批次与随机数状态，读档后暂停。

## 未实现 / 限制（后续阶段）

- 完整外部星球毁灭、竞争期限、最后出口关闭、留居结局。
- 镇压、夺权事件与战斗；列车长亲自探索玩法；封闭车厢解锁剧情；离开交易站后的航线。
- 完整 10 人负责人候选池与人物故事（当前为临时测试名单）。
- 重要探索场景只有一个简短事件。
- 所有数值是原型参数，未做最终平衡。不调整需求奖励的被动玩法有可能来不及离站（多种子测试中约 2/5 失败）。
- 浏览器存档使用 localStorage，隐私模式下可能不可用（界面会提示）。

## 项目结构

```
src/
  config/balance.ts   所有可调数值（时间、价格、产量、耗时、概率）
  config/content.ts   物品、配方、研究、临时名单、星球模板、事件
  sim/                纯逻辑模拟（无 DOM），固定步长 1 游戏分钟
    state.ts          初始状态
    step.ts / clock.ts  主循环与实时时钟（暂停/加速）
    groups.ts         编组规则
    groupAI.ts        小组状态机与目标选择
    claims.ts         作业位置占用/保留/释放
    economy.ts        结算、贡献点、自主购买
    train.ts          扫描、加工、维修、研究
    survival.ts       生存与情绪
    catastrophe.ts    灾变
    actions.ts        列车长操作（每个都有禁用原因）
    save.ts           版本化存档
    objectives.ts     阶段目标
  ui/                 界面（面板、列车剖视、星球地图）
tests/                vitest：规则测试、完整流程、多种子
```

## 测试

`npm run check` 运行类型检查与 21 项测试，覆盖：暂停冻结与加速一致性、先到先得与保留/到期释放、等待不超时、批次只结算一次、库存/资金不足时拒绝、存读档后继续运行结果完全一致且不重复发奖、配属座机、强行离站、两组自主行动全程不变量检查，以及多种子从开局走到交易站。
